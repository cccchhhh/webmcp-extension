# 轻量桥接连接与页面共享

服务端代码统一位于 `webmcp-server`，插件只负责浏览器页面发现、授权与执行。

1. 在服务端项目构建并运行 `node dist/cli.js init`。已有轻量桥接凭证时跳过初始化。
2. 使用 `node dist/cli.js serve` 启动服务端，无需配置插件 Origin 白名单。
3. 插件填入 `http://127.0.0.1:38472` 和初始化输出的 `plugin.token`，保存后开启连接。远程部署填写 HTTPS origin，不包含 `/mcp`。
4. 在目标网页允许插件访问该站点。完成工具发现后，默认共享页面及全部可执行工具，可在「页面共享」关闭共享或取消单项授权。
5. AI 客户端连接 `http://127.0.0.1:38472/mcp`，使用独立的 `agent.token` 作为 Bearer 请求头。依次发现页面、读取目录、调用工具。

插件令牌只适用于实现本项目桥接协议的服务；不能使用任意 MCP 服务器的令牌替代。浏览器身份自动生成并持久化，无需设备注册或 Agent 设备授权。

关闭侧边栏不影响后台执行；连接中断后自动重连并登记共享目录，不重放调用。浏览器完整重启或扩展重载后，会话共享记录和历史清空；重新发现页面后应用默认共享。导航后旧页面和调用目标失效，新页面重新发现后默认共享。全部授权时目录新增工具自动共享；手动取消单项授权后，不自动添加新工具。超时或取消无法确认时显示「结果未知」，原执行结束前保留锁。

切换服务地址或身份会清空共享并按默认规则为可用页面重新建立共享。更换插件令牌或清除凭证会重建浏览器身份。旧服务配置升级时停用并清除旧凭证和共享，不会自动发送到新服务。

- `CONNECTION_FAILED`：确认服务进程已启动、地址可访问及 HTTPS 证书有效。
- `HTTP_401`：确认填写的是有效插件令牌，未被轮换或撤销。
- `HTTP_403`：检查是否误填 Agent 令牌，以及服务端 Host 配置。
- `HTTP_409`：浏览器身份绑定了其他凭证 ID，需轮换原凭证或撤销后重新接入。
- `SERVICE_PERMISSION_REQUIRED`：重新保存配置并授予服务地址权限。
- `CATALOG_SYNC_FAILED`：检查目录格式、载荷大小和服务端日志。

协议见 [桥接协议 v1](bridge-protocol.md)，测试入口与当前结果见 [验收报告](bridge-test-report.md)。
